# Neon PostgreSQL setup

Configured on 2 November 2026 for organization org-bitter-sound-42564104, project Rally (hidden-thunder-01508196), branch production (br-lively-mode-b3aztjue).

Only PostgreSQL is used. Existing ASP.NET Core authentication and authorization remain in place. Neon deploy configures backend services; the React/.NET app still runs locally or on a separate application host.

## First-time setup

Requires Node.js 24 and .NET SDK 10.0.303. From the repository root:

```powershell
npm i -g neon@latest
neon login
neon init -y --org-id org-bitter-sound-42564104 --project-id hidden-thunder-01508196 --branch production --services postgres --no-agent-setup
npm ci
npm ci --prefix web
neon deploy
npm run build
npm start
```

The --no-agent-setup flag skips editor plugin installation; the Neon skills are already installed. The initial plugin installation stalled, so setup continued with this option. If the CLI cannot reach Neon because this environment uses Windows-installed certificate authorities, enable system trust in the same terminal:

```powershell
$env:NODE_USE_SYSTEM_CA = '1'
```

Do not disable certificate checking. If sign-in is missing, complete neon login in the browser and retry.

The app defaults to http://127.0.0.1:5082. Set RALLY_PORT to change it. This avoids the existing native development server on 5080. Stop npm start before republishing into .local/publish on Windows.

## Configuration and connection handling

neon.ts preserves the generated branch policy and declares no additional services. PostgreSQL exists on every Neon branch. The explicit auth:false generated by init was removed so deploying this PostgreSQL-only integration cannot disable an existing Neon Auth configuration.

The local project pointer .neon and all .env files except .env.example are Git-ignored. Neon deploy writes DATABASE_URL (pooled), DATABASE_URL_UNPOOLED (direct) and NEON_BRANCH into .env.local, or .env when that file already exists.

scripts/start-neon.mjs loads environment files server-side; injected environment variables take precedence, followed by .env.local and .env. Credentials are never included in React bundles. It explicitly selects Neon over inherited local ConnectionStrings__Rally settings.

Npgsql remains the database driver for this long-running .NET API. DatabaseConfiguration converts standard PostgreSQL URLs into safely quoted Npgsql options, decodes credentials, preserves required channel binding, and uses full TLS certificate and hostname verification for Neon. Application requests use the pooled URL with a maximum local pool size of 20; startup schema initialization uses the direct URL. The tracked Database.Schema remains the source of the initial idempotent schema.

The existing local PostgreSQL and Docker Compose workflows still use ConnectionStrings__Rally and optional Database__Password. Outside the Neon launcher, explicit ConnectionStrings__Rally takes precedence over DATABASE_URL.

The native local database has not been migrated into Neon. Register an account in the Neon-backed app to start using it. Verification created uniquely named test accounts and a Verification club in the selected branch.

## Hosted app

Provide DATABASE_URL and DATABASE_URL_UNPOOLED to the .NET container through the host's secret configuration. Do not bake .env files into images. For a public domain, configure AllowedHosts for that domain and terminate HTTPS at the hosting platform. Preserve the Data Protection key directory across restarts where supported. Neon hosts the database; this task did not publish a public frontend.
